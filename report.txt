题目
面向学习场景的智能台灯系统设计与姿态检测方法研究
摘要
概述研究背景、系统目标、主要方法、实现结果和意义。
重点写：多传感器感知、姿态识别、个性化标定、自动灯光调节、学习状态监测。
关键词
智能台灯；姿态检测；YOLO Pose；多传感器融合；个性化标定；智能照明
1 引言
1.1 研究背景
写学生居家学习场景中存在的坐姿不良、光照不适、用眼距离过近等问题。
1.2 研究意义
说明智能台灯不仅是照明设备，还可以成为学习行为与健康状态的感知入口。
1.3 研究目标
本项目目标包括：环境感知、人体在位检测、距离异常提醒、姿态异常检测、灯光自动调节、前端可视化管理。
1.4 本文主要工作
可以概括为四点：
第一，设计 ESP32-S3 多传感器采集系统。
第二，搭建 Flask 后端与 Vue 前端监控平台。
第三，实现基于 YOLO11n-pose 的姿态检测流程。
第四，引入肩宽归一化和个性化标定，提高不同用户与机位下的适应性。
2 相关技术与理论基础
2.1 智能照明与学习健康监测技术
介绍智能台灯、环境光检测、距离检测、自动调光等背景。
2.2 人体姿态估计技术
介绍人体关键点检测、YOLO Pose、关键点置信度、人体框、姿态标签等概念。
2.3 多传感器数据采集技术
介绍 AHT20 温湿度传感器、BH1750 光照传感器、VL53L0X 距离传感器、摄像头模块。
2.4 基于规则的状态判断方法
说明本项目采用“模型推理 + 几何特征 + 阈值规则 + 时序平滑”的混合方法，而不是完全依赖黑盒模型。
3 系统总体设计
3.1 系统需求分析
功能需求：环境监测、距离判断、姿态识别、自动调灯、事件记录、学习摘要、前端展示。
非功能需求：实时性、稳定性、低成本、可扩展性、局域网部署。
3.2 系统总体架构
建议放一张系统架构图。
分为四层：
设备感知层：ESP32-S3、传感器、摄像头。
数据服务层：Flask API、SQLite、状态处理。
智能分析层：姿态检测、规则引擎、策略引擎。
应用展示层：Vue 前端、监控面板、台灯绑定与控制。
3.3 数据流设计
传感器数据上传到后端；摄像头帧上传或本地推理；后端融合传感器和姿态结果；策略引擎输出灯光控制动作；前端展示状态和历史记录。
3.4 系统模块划分
设备端模块、后端 API 模块、姿态识别模块、台灯控制模块、前端可视化模块。
4 硬件与设备端设计
4.1 设备端硬件组成
ESP32-S3 作为主控，连接 AHT20、BH1750、VL53L0X 和摄像头模块。
4.2 传感器采集逻辑
温湿度每 30 秒采集，光照每 10 秒采集，距离每 1 秒采集，心跳定期上传。
4.3 设备端状态机设计
根据距离判断 present、away、unknown；根据光照、温度、湿度生成环境标签；根据状态变化上传事件。
4.4 摄像头数据采集与上传
摄像头用于学习姿态分析和异常事件快照，支持定时上传帧以及异常事件关联快照。
5 后端服务与自动控制策略设计
5.1 Flask 后端接口设计
包括设备数据上传、事件上传、心跳、配置下发、摄像头帧上传、姿态分析、台灯绑定与控制等接口。
5.2 数据存储设计
使用 SQLite 保存 telemetry、事件、派生状态、学习摘要、台灯绑定状态等数据。
5.3 学习状态推断方法
后端融合距离、环境、姿态结果，得到 idle、studying、warning、unknown 等学习状态。
5.4 自动照明控制策略
根据是否在位、环境光照、学习模式、离座时长进行自动开关灯、调亮度、调色温。
例如环境过暗提高亮度，离座一段时间后调暗或关灯，阅读模式提高亮度，电脑模式降低亮度。
5.5 米家台灯控制与手动覆盖机制
说明通过米家 API 实现台灯绑定与控制，并保留手动控制优先级，避免自动控制频繁打断用户。
6 姿态检测算法设计
6.1 姿态检测流程
输入视频帧，经 YOLO11n-pose 获得人体框与关键点；选择桌前目标用户；提取姿态几何特征；规则引擎判断距离与姿态；时序平滑后输出事件。
6.2 目标用户选择
介绍 ROI 或目标区域约束、人体框重叠度、关键点置信度、短时间保持上一目标等机制。
6.3 姿态特征提取
包括肩宽、人体框面积比例、鼻尖到肩中心距离、头部倾斜角、躯干倾斜角、颈椎角、关键点有效比例等。
6.4 肩宽归一化方法
这是报告的重点之一。
说明传统像素阈值容易受距离、身高、摄像头机位影响，因此引入肩宽作为尺度基准，将头肩距离、人体距离等转换为相对比例。
6.5 个性化标定方法
用户正常坐姿时采集参考肩宽、人体框面积、头肩距离比例、躯干角度、头部倾角，后续判断基于“相对正常坐姿的偏差”。
6.6 姿态规则判断
包括：
在位检测：seated_candidate、seated、absent。
距离判断：normal、near、too_close。
姿态异常：head_down、leaning_left、leaning_right。
事件触发：异常持续一定时间才报警，并设置冷却时间。
6.7 时序平滑与误报抑制
说明 label smoothing、warning hold seconds、cooldown seconds 的作用，避免单帧误检导致频繁提醒。
7 前端可视化与交互设计
7.1 前端总体功能
Vue 3 + TypeScript 实现监控面板、传感器卡片、事件时间线、历史趋势、学习摘要、台灯绑定与手动控制。
7.2 实时监控页面
展示当前温湿度、光照、距离、学习状态、台灯状态。
7.3 事件与学习摘要展示
展示离座、距离过近、环境异常、姿态异常等事件，并生成学习时长、离座次数、提醒次数等摘要。
7.4 台灯绑定与控制页面
支持扫码登录米家、获取设备列表、绑定台灯、设置亮度和色温。
8 实验设计与结果分析
8.1 实验环境
说明硬件环境、软件环境、模型版本、摄像头分辨率、配置参数。
8.2 测试数据来源
包括公开学习姿态视频、自采实验数据、样例图片和视频。
8.3 评价指标
建议使用：在位识别率、异常触发率、误报率、漏报情况、处理帧率、事件延迟、系统稳定性。
8.4 姿态检测实验结果
可以写已有结果：
正常离座识别较准确；正常学习场景可进入 seated；reading/computer 场景需要不同阈值；侧视角下 hip 关键点不稳定，颈椎角和躯干角存在局限。
8.5 归一化方法效果分析
说明肩宽归一化改善了对不同用户体型和不同距离的适应性，避免完全依赖人体框像素面积。
8.6 系统联动实验结果
写传感器数据上传、后端状态推断、前端展示、自动调灯策略能够形成闭环。
9 讨论
9.1 项目优势
系统完整，覆盖硬件、后端、前端和算法；规则透明；支持个性化标定；具备真实产品化雏形。
9.2 当前不足
桌面感知能力不足；不同机位下 ROI 和阈值仍需调节；侧视角下部分人体关键点不稳定；真实台灯安装场景数据仍然不足。
9.3 改进方向
加入桌面平面标定；采集真实台灯机位数据；区分阅读和电脑使用模式；训练或微调专用姿态分类模型；优化端侧部署性能。
10 结论
总结本文完成了一个面向学习场景的智能台灯系统，融合环境传感、距离检测、姿态识别和自动照明控制。重点强调项目证明了“多传感器 + 姿态估计 + 个性化规则”的可行性，为后续健康学习辅助设备提供了实现基础。
